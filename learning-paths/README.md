# Rutas de aprendizaje por perfil

Las rutas reducen alcance, no eliminan prerrequisitos. Antes de saltar una parte, completa su
proyecto o demuestra evidencia equivalente.

| Perfil | Partes principales | Resultado |
|---|---|---|
| Cloud Engineer AWS | 00, 01, 02, 05, 07, 10, 11, 14 | Plataforma AWS operable y gobernada |
| Cloud Engineer Azure | 00, 01, 03, 05, 07, 10, 11, 14 | Plataforma Azure operable y gobernada |
| Cloud Engineer GCP | 00, 01, 04, 05, 07, 10, 11, 14 | Plataforma GCP operable y gobernada |
| DevOps Engineer | 00, 05, 06, 07, 08, 10, 11 | Flujo de entrega cloud-native |
| Platform Engineer | 05, 06, 07, 08, 10, 11, 14 | Internal Developer Platform |
| SRE | 00, 05, 06, 08, 10, 12, 14 | Servicio gobernado por SLO |
| Cloud Architect | 01–04, 09, 11–14 | Arquitectura defendible multi-cloud |
| Cloud Security | 00, 01, un proveedor, 05–08, 11, 14 | Landing zone y guardrails |
| FinOps Practitioner | 01, un proveedor, 08, 10, 11, 14 | Modelo de asignación y optimización |
| Data / Integration Engineer | 01, un proveedor, 05–10, 12 | Plataforma de datos orientada a eventos |

## Selección del proveedor

Estudia un proveedor en profundidad antes de comparar tres. Para una ruta portable, completa
las 12 clases del proveedor principal y los proyectos finales de los otros dos. La comparación
debe hacerse por identidad, red, cómputo, datos, observabilidad y gobierno, no por equivalencias
nominales de servicios.

## Evidencia de salida

Todas las rutas terminan con un repositorio de portafolio que incluye arquitectura, ADR,
infraestructura reproducible, pipeline, SLO, runbooks, threat model, estimación de costo y
demostración de fallo/recuperación.
